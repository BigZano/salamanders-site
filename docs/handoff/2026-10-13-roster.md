# Handoff: Roster built and designed (2026-10-13)

For the Windows workstation session. The data side is done on **Vulkan**. This
repo is public, so this document holds no secrets and no real member names.

## What exists

- `GET /roster` and `GET /roster/infirmary` on the builds API (Spec:
  `docs/superpowers/specs/2026-10-13-roster-design.md`). Live from Discord, in server
  memory only, gated to the XVIIIth Legion (the Infirmary list to company
  command and up).
- The `/roster` page, designed and built on branch `feat/roster-design` (spec:
  `docs/superpowers/specs/2026-10-13-roster-design-pass-design.md`; the approved visual
  and behaviour reference is the mock in
  `docs/superpowers/specs/2026-10-13-roster-design-pass-mock/`).
  `src/views/Roster.vue` composes small pieces from `src/components/roster/`, and the
  page's shape comes from one pass over each snapshot in `src/lib/rosterView.js`.
  Branches start collapsed; an opened branch pours a heat-graded spine down its
  ranks. There is a High Command dais, a status line (gaps link to their branch),
  **Find me**, Expand all, and `/roster#company-3` deep links. Hooks the tests and
  e2e use are listed in `src/components/roster/roster.css` (new: `data-jump`,
  `data-open`, `.rs-find`, `.rs-expand-all`, `.rs-me`).

## Run it without the live server

```pwsh
$env:VITE_ROSTER_FIXTURE = '1'
bun run dev
```

Then open `/roster`. The page reads `src/data/roster.fixture.json`, a
**synthetic** roster (invented names, the real role structure) produced by
`node scripts/roster-fixture.mjs`. It includes a vacant company (6th), an
acting head (2nd), a Venerable Dreadnoughts branch, Dreadnought side slots
(`aside`), a Reclusiam branch, a 24-deep Scout waterfall, a Terminator
(`lateral`), a company/name mismatch, and an Infirmary list. The fixture loads
only in dev with that variable set; it is not in the production bundle. If you
want a new case, add it in `scripts/roster-fixture.mjs` and regenerate (a test
fails if the committed file and the generator drift apart).

Switch scenes without restarting the dev server by adding `?scene=<name>` to
the URL (it reloads the page), or set `VITE_ROSTER_FIXTURE=<name>`. A dev-only switcher (`.rs-dev-scenes`, top of the
page) links to each: `full` (everything), `stale`, `empty` (every head vacant),
`loading`, `signin`, `denied`, `error`. They are built in `src/lib/rosterScenes.js`.

Styles live with their components (scoped, in `src/components/roster/*.vue`);
`roster.css` is a hook reference. One trap: never write `:global(x) .y` in a
scoped block. Vue drops everything after `:global()`, so it becomes a bare
`x { ... }` rule (here it rotated every open panel). Cross-component rules go in
an unscoped `<style>` block; `src/components/roster/styles.test.js` guards this.

Running tests: if `VITE_ROSTER_FIXTURE=1` is set in your shell (the run
instructions above set it), unset it first. It makes the roster store return
fixture data instead of the mocked API, and 22 roster tests fail. Use
`env -u VITE_ROSTER_FIXTURE bun run test`.

## The data contract

`GET /roster` returns `{ fetchedAt, stale, viewer: { infirmary }, highCommand,
branches, unassigned, servitors }`.

- `highCommand`: `[{ rank, members }]`, rank order, empty ranks omitted.
- `branches`: always 12, in order: companies 1–7, `venerable-dreadnoughts`,
  `forge`, `librarius`, `apothecarion`, `reclusiam`. Each has `key`, `label`, `kind` (`company`, `dreadnoughts` or `specialty`),
  `number` (companies only), `head` (`rank`,
  `members`, `vacant`), `aside` (Dreadnoughts: honoured, no formal post, drawn
  between the head and the Lieutenants, off to the side) and `rows`
  (`[{ rank, members }]`, top to bottom, empty rows omitted). Only these
  branch rows carry `data-tier` and `data-lateral` in the current markup; the
  High Command and Unassigned rows carry `data-rank` only.
- `unassigned`: `{ rows: [{ rank, members }] }`, with no head.
- `rank = { key, label, tier, lateral? }`. **Ranks sharing a `tier` are peers**:
  set them side by side, best effort (Company Ancient and Company Champion).
  `lateral` (Terminator) is a specialization of the rank and file, not a step
  toward Sergeant: draw it beside the ladder if you like.
- Head rows across the page are peers too: Captains and Venerable
  Dreadnoughts share tier 1.
- `Member = { id, name, avatar|null, company|null, alsoCompanies?, acting?,
  nameMismatch?, bot? }`. `avatar` is a CDN URL or null (render initials).
  `company` comes from roles only. `acting` marks an acting head (a company
  with no Captain; the person also stays where they already are). A High
  Command member who is also a Captain appears in both the banner and their
  company's head row, unlabelled: `acting` is only for a company with no
  Captain.
  `nameMismatch` means the display name claims a different company than the
  roles: show a subtle marker so leadership can fix whichever is stale.
  `alsoCompanies` lists extra company roles after the one that placed them.
- `servitors`: `[{ id, name, avatar, company: null, bot? }]`, the viewing accounts and bots, shown as a deliberate joke at the
  foot of the page.
- `GET /roster/infirmary` returns `{ fetchedAt, stale, count, members }`; each
  member has `rank` (or null if rank roles were stripped), `legion` (they still
  hold the Legion role, which they should not while on leave) and the `Member`
  fields. It lists every holder of the Infirmary role, Legion role or not.
  Infirmary holders never appear on the main roster.

The page polls every 60 s while the tab is visible, so people who leave the
server disappear without a refresh. `stale: true` means the server could not
refresh for over twice `ROSTER_TTL_MS` (ten minutes at the default); say so.

## Placement in one paragraph

Roles decide, in order: High Command banner; Master of the Forge, Chief
Librarian, Chief Apothecary head their branches; Captains head their company
(a Captain who is also a Venerable Dreadnought is shown with their company; a
Captain with no company role falls through to the Venerable Dreadnoughts branch if they hold that role); Venerable
Dreadnoughts are their own branch; other Dreadnoughts sit aside in
their company; the Reclusiarch heads the Reclusiam; other specialty roles fill
their branch's waterfall (with a company tag); everyone else goes in their
company's waterfall, or Unassigned. Firedrake roles imply the 1st Company and
Scout Sergeant the 7th, but only when no company role is held. Full rules, with
every role id, are in the spec.

## Measured (design pass)

Budgets are in the spec, section 5. Numbers from 2026-10-13, Windows workstation.

| Check | Result |
|---|---|
| Roster route chunk, JS + CSS gzipped (budget 25.6 KB) | 10.1 KB (JS 6.0, CSS 3.5, shared `PageHeader` 0.7); the fixture is not in the bundle |
| New runtime dependencies | none |
| `buildRosterView` per snapshot | 0.08 ms on the committed fixture, 0.15 ms at 5x (node) |
| Load to a built DOM, dev build, native speed (budget 50 ms at 4x throttle for ~200 members; 150 ms for ~1,000) | 19 to 32 ms for 217 chips, 1,416 DOM nodes; 67 to 113 ms for 949 chips, 3,612 DOM nodes (the 113 is the cold first run) |
| Unchanged poll | assigns nothing and rebuilds nothing (unit-tested) |
| Reader's bar during Expand all / Collapse all; Find me and status-link landing; frames | measured on the mock: 0 px, 0 px, 60 fps with a worst frame of 17 ms (see the spec, section 5) |

Not yet measured on the real page, and why: the 4x CPU throttle (the browser tool
cannot set it; the dev-build numbers above are native), and the frame-rate,
reader-pinning and landing checks (the browser window was in the background during
the run, so there were no animation frames to sample). To finish them: bring the
window forward, write the 5x fixture (`node scripts/roster-fixture.mjs --scale 5
--out src/data/roster.fixture.json`), run `VITE_ROSTER_FIXTURE=1 bun run dev`, and
use the sampler in the mock folder (`bench.js`; its README says how). Restore the
fixture afterwards with `git checkout -- src/data/roster.fixture.json`.

The e2e specs added for Find me, Expand all and the `#company-3` link are written
but have not been run: e2e only runs on Vulkan.

## Deploy (when the design is merged)

No new secrets. On Vulkan: `cd server && docker compose up -d --build api`.
Optional env `ROSTER_TTL_MS` (default 300000). Check:
`curl -s -o /dev/null -w '%{http_code}\n' https://builds-api.armorybot.win/roster`
should print `401`. Rollback: redeploy the previous image; nothing is stored,
so there is nothing to clean up.
