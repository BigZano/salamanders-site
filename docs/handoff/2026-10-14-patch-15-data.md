Branch `feat/patch-15-data` (worktree `.claude/worktrees/patch-15-data`), 2026-10-14. Spec: `docs/superpowers/specs/2026-10-14-patch-15-data-refresh-design.md` (read its Amendment first). Plan: `docs/superpowers/plans/2026-10-14-patch-15-data-refresh.md`.

Not merged and not pushed. No server, schema or Docker change. Nothing here needs a Vulkan deploy by itself, with one possible exception (see "Perk corrections").

## What shipped

- **Defence type per melee version** (Block, Balanced or Fencing), parsed from the wiki's `Defence` column. The Armoury shows a badge beside "Statistics" and the type in the version dropdown. The wiki's "Balance" reads "Balanced".
- **One-Handed Thunder Hammer**: 10 versions (Standard to the Heroic Power Maul) and a 20-perk tree copied from your in-game list (`docs/handoff/sources/`). Also the Frost Axe (Power Axe) and Iron Hands (Auto Bolt Rifle) heroics. The original Thunder Hammer reads "Two-Handed Thunder Hammer" and the Techmarine axe reads "Omnissian Axe" in the UI; the keys saved builds use are unchanged. A weapon with no perk tree on the wiki shows "Perk tree not published yet".
- **Class melee lists**: Tactical gains Power Sword, Power Axe and One-Handed Thunder Hammer; Assault and Bulwark gain One-Handed Thunder Hammer; Techmarine gains Thunder Hammer and One-Handed Thunder Hammer.
- **Tactical rework**: 11 grid slots changed, *Passive Chambering* replaces *Exigency Charge*, the starting-perk text is updated, and level 6 is *Improved Efficiency* (the wiki lists *Marksman's Mandate* twice). Sources are recorded in `src/data/patch-overrides.json`.
- **All other wiki drift is adopted** (see below), with Heavy's prestige perk kept by an override, and Assault level 14 is now *Furious Strikes*.
- **Saved-build migration** for Tactical (11 slots, *Marked for Death*, the prestige perk) and Assault (level 14). It runs when a build is loaded in the builder, from a share link, or from local storage. Replaced perks are dropped along with their notes; reworked ones are kept and flagged. The builder shows a "Perks changed" notice, per class, and gallery cards show a "Needs review" chip. Nothing is stored in the database.
- **Bake flags** `wiki:perks -- --classes X` and `wiki:weapons -- --keep-perks` still exist for cases where a refresh should hold something back. Neither is needed now.
- `last-patch.json` records **Hotfix 15.1 (8 October)**.

## What changed after the first review: the hold rule was wrong

I first held back wiki edits that the Patch 15.0 notes did not mention, on the rule "uncorroborated means false". A cross-check against sealed.build's datamined Hotfix 15.1 game data (read once into scratch space, not copied; see `docs/ideas/2026-10-14-sealed-build-review.md`) showed that was wrong:

- Every held edit their data covers was true: **60 class perk edits, 102 weapon perk edits and 23 weapon version stat edits**. For the stat edits only the PvE numbers could be checked: the game data has no PvP figures, so the PvP half of five magazine figures (Plasma Incinerator, Las Fusil, Heavy Bolter, Heavy Plasma Incinerator, Multi-Melta) is adopted from the wiki unverified. All **four Tactical pins** were false (Balanced Distribution 15%, Heightened Vigour with Block, Plasma Boost on all Plasma Weapons, Relentless Pursuit 10 seconds). The wiki had been behind in September and has since caught up; older patch notes (for example Hotfix 12.2 on Moving Target and Retribution) already backed some of the edits.
- **Hotfix 15.1 also changes the Melta Rifle** (default magazine 6, ammo pool 12, falloff distances). My earlier note that it touched only the One-Handed Thunder Hammer was wrong.
- **One exception:** the wiki swaps Heavy's prestige perk *Honed Precision* for *Restorative Capacity*; the game data keeps *Honed Precision*. An override keeps it, and the bake warns when the wiki agrees again.
- Both bakes were re-run with no hold flags. Result: 66 class perk texts and the Assault grid slot updated, weapon perks and stats refreshed, the old repeated and mislabelled Bolt Carbine versions cleaned up (it now has the 12 versions the game has).

## Perk corrections

Three bundled corrections (ids 19, 32 and 33 in `src/data/perk-corrections.json`) were redundant and left the snapshot:

- **32 and 33** (Inferno Pistol: remove *Motivated Melee*, add *Know No Fear*) became redundant because the wiki now agrees with your September fix, which is also confirmation that the fix was right.
- **19** (*Divine Might* on the Heavy Bolt Rifle, Relic) was already redundant before this branch: the bake has always had that perk, so it shows twice on `main` today. Dropping the correction fixes that.

A saved weapon-perk pick of the duplicate (added) copy of *Divine Might* (Heavy Bolt Rifle) or *Know No Fear* (Inferno Pistol) has a different id from the baked copy, so it comes back unselected after this lands; picks of the baked copies are unaffected. A new test (`perkCorrections.test.js`, "no bundled addition is already in the bake") catches a redundant correction after any re-bake.

**If the corrections were already seeded into the live database on Vulkan**, revert those three in the corrections editor (the deploy re-snapshots the live corrections before building, so the repo edit alone would not stick). If the go-live has not happened yet, the seed file already excludes them.

## Still different from the game data (not changed)

From a full audit (168 class perks, 168 grid slots, 49 prestige perks, 535 weapon perks, 288 weapon versions, 1,808 stat cells). Matches: 165 of 168 class perks (two spellings and *Omnissiah's Fury*, whose wiki text carries a damage table), 167 of 168 grid slots (a spelling), 43 of 49 prestige perks (four differ in punctuation only; the other two are the names in item 6), 515 of 535 weapon perks after your corrections (the other 20 are below). The rest:

- **Values the wiki still seems to have stale:** *Perpetual Velocity* is 20% on the Plasma Incinerator (Relic) and Las Fusil (Standard, Artificer) but 15% in the game data; Bolt Carbine One-Handed (Relic) *Honed Precision* and *Elite Hunter* are 50% against 25%; *Decisive Reload* wording on the Melta Rifle and Multi-Melta; *Omnissiah's Fury* carries a per-difficulty damage table the game data lacks. The Range gauge of the Melta Rifle and Multi-Melta (Master-Crafted Alpha, Salvation of Bakka) reads 2+ and 3+ where the game data has 4.5 (Hotfix 15.1 moved their falloff start to 5 m).
- **Heroic perks we do not carry:** Auto Bolt Rifle *Furious Salvos*, Heavy Bolt Rifle *Auxiliary Grenade Launcher*, Power Axe *Howl of Fenris*, Combat Knife *Scathing Retort* (our data has *Knuckles*), One-Handed Thunder Hammer *Crackling Hammerfall*.

## Known gaps (not fixed)

- **Weapon key shown, not the in-game name.** The Planner loadout summary, the Armoury "equipped" toast and the copied build text still say "Thunder Hammer" (and "Omnissiah Axe"), where the Armoury list, hero, version picker, weapon slot and gallery card say the in-game names. Spec B+C reworks the loadout area.
- **Reworked-perk cutoff.** It is the game patch date (1 October). Gallery builds saved between the patch and this deploy are written against the old *Marked for Death* text but are not flagged.
- **Weekly run with a broken class page.** With no flag, one class page whose grid cannot be derived aborts the whole run, so the weapon bake never runs. Pin and override warnings appear only in the job log, not the PR body.
- **Removed weapons.** A weapon removed from `weapons.json` stays in `weapon-trees.json` (the merge keeps every previous-only weapon).
- **Live fallback.** The live-wiki fallback parser does not read `Defence`, so only baked weapons get the badge.
- **Gallery card.** It assumes a build's `perks` is an array (as before this branch; the API always sends one).
- **Version dropdown.** The closed dropdown cuts long labels off (an existing 16rem width limit); the type is in the badge.

## Deploy and the weekly workflow

- The API reads the bake from `main` on GitHub with a 10-minute cache (`server/src/bake.js`), so once this is merged no redeploy is needed for the data.
- The weekly `data-check` workflow runs `wiki:all`. With the drift adopted, its PRs should be small again. Overrides in `patch-overrides.json` are re-applied each run and warn in the job log when one has gone stale (the wiki caught up). The PR text now says the tests are not run on the PR: run them on the PR branch first.
